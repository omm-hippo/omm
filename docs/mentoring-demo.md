# 멘토링 시연·평가 자료

관련 이슈: #421(로컬 웹 관리 화면), #423(초보자 설치·첫 실행), #433(사용자 데모·평가).

이 문서는 시연 순서와 평가 기록 양식을 정리합니다. **실제 사용자 평가 결과나 성과 수치는
아직 없습니다.** 아래 표와 양식은 비어 있는 상태로 두고, 실제로 해 본 뒤에만 채웁니다. 자동
테스트 결과를 사람 평가로 바꿔 적지 않습니다.

## 1. 누구를 위한 것인가

첫 대상: **로컬 LLM을 처음 설치해서 써 보려는 사람.** 명령줄이 익숙하지 않은 학생·직장인을
생각합니다.

이 사람들이 겪는 불편(멘토링에서 나온 문제):

- 설치 가이드를 읽고도 Python·git·PATH 단계에서 막힌다.
- 내 PC(RAM·VRAM)에 어떤 모델이 맞는지 모른다.
- Ollama, LM Studio 같은 실행기마다 모델을 따로 받아 저장 공간이 두 배로 든다.
- 모델을 받았는데 실제로 답을 하는지 확인하는 방법을 모른다.

OMM의 역할:

- 설치 스크립트가 Python·git을 가능한 범위에서 자동 설치하고, 실패하면 이유를 출력한다
  ([beginner-install.md](beginner-install.md)).
- 실제 하드웨어를 읽어 맞는 모델을 추천한다 (`omm recommend`, 웹 **추천**).
- 모델 파일을 한 곳(`OMM_HOME`)에 받고 실행기마다 링크해서 중복 저장을 줄인다.
- 실행기에 짧은 질문을 보내 실제 응답을 확인한다 (웹 **실행 확인**, `omm verify`).

## 2. 시연 체크리스트

시연 전 준비:

- [ ] 시연용으로 따로 `OMM_HOME`을 정한다. 평소 쓰는 모델 폴더를 건드리지 않는다.
- [ ] Ollama 또는 LM Studio를 설치하고 로컬 서버를 켜 둔다. (웹 응답 확인은 이 둘만 지원)
- [ ] 작은 모델 하나를 받을 수 있는 디스크 공간과 인터넷 연결을 확인한다.
- [ ] 시연 OS를 기록한다(아래 4번 표의 어느 열을 확인하는지).

순서 (설치 → 추천 → 모델 설치·공유 → 실행 → 첫 응답):

1. **설치.** OS에 맞는 설치 명령을 실행한다 ([beginner-install.md](beginner-install.md) 1번).
   마지막 줄에 `omm web --open`과 `omm web --create-launchers` 안내가 나오는지 본다.
2. **새 창 열기.** 새 터미널 창에서 `omm`을 실행해 처음 설정(하드웨어 표, 실행기 목록)을 본다.
3. **관리 화면 열기.** `omm web --open` → 브라우저에서 왼쪽 메뉴를 보여 준다.
   주 메뉴: 모델 찾기 · 추천 · 내 모델 · 채팅 · 내 문서 · 성능 비교 · 작업.
   관리 메뉴: 연결 상태 · 진단 · 파일·설정.
4. **추천.** **추천** 화면에서 이 PC의 메모리와 추천 근거를 보여 준다.
   CLI로는 `omm recommend`.
5. **모델 설치·공유.** 모델을 골라 설치를 확인하고, 실행기를 고른다. **작업** 화면에서 진행
   상황을, **내 모델**에서 설치된 파일·용량·실행기 연결을 확인한다.
   CLI로는 `omm install <모델>` 후 `omm list`, 저장 공간 요약은 `omm scan`.
6. **실행(첫 응답).** **내 모델**에서 **실행 확인**을 누른다. 실제로 돌아온 짧은 응답 문장을
   보여 준다. 이 확인은 "로컬에서 글이 생성된다"는 뜻이지 답의 품질을 뜻하지 않는다고 말한다.
7. **대화.** **내 모델 → 대화**로 **채팅** 화면을 열어 질문 하나를 보낸다.
8. **(선택) 내 문서.** 텍스트 PDF나 TXT를 등록하고 질문해서 출처 구간이 함께 나오는지 본다.
9. **정리.** 웹에서 시연용 모델을 삭제하고, 파일·실행기 연결이 같이 정리되는지 본다.
10. **(선택) 더블클릭·자동 시작.** `omm web --create-launchers "$HOME/Desktop"`으로 만든
    `Open-OMM` 파일을 더블클릭한다. 자동 시작은 `omm setting web-autostart enable`로 켜고
    `status` 확인 후 `disable`로 끈다(기본은 꺼짐).

시연 중 확인할 것(이슈 #433 완료 기준): 실제 요청, 설치된 파일, 등록 상태, 실행기의 첫 응답.
화면만 보여 주거나 테스트용 가짜 응답으로 대신하지 않는다.

## 3. 평가 기록 양식

사람을 모집하거나 연락하는 일은 이 문서로 시작하지 않습니다. 실제 평가를 할 때 참여자 한 명당
아래 양식을 하나씩 복사해서 채웁니다. 이름·연락처 같은 개인정보는 적지 않습니다.

## 4. 기능 상태표

표 읽는 법:

- **구현**: 코드가 들어가 있음.
- **자동 테스트**: 저장소의 pytest가 그 경로를 검사함. CI는 Python 테스트를 Linux·macOS·Windows에서
  돌린다(`.github/workflows/ci.yml`). OS별 건너뛰는 테스트는 따로 적었다.
- **실사용 확인**: 실제 기기·실제 브라우저·실제 실행기에서 사람이 확인한 기록이 있음.
- **미검증**: 위 기록이 없음.

macOS·Windows·Linux 열은 "실사용 확인" 상태입니다. 근거가 없으면 모두 미검증으로 둡니다.

| 기능 | 구현 | 자동 테스트 | macOS 실사용 | Windows 실사용 | Linux 실사용 |

- 주1: PR #434 본문에 "이 Mac에서 별도 OMM_HOME으로 실제 로컬 HTTP 서버를 실행해 세션 시작,
  번들 파일 반환, 설정 저장, 재시작 후 재조회를 확인"한 기록이 있다. 브라우저 화면 조작과
  실제 실행기 생성은 그 기록에서도 미검증이다. 이후 변경에 대한 재확인은 아니다.
- 주2: Linux에는 `.command`/`.cmd`를 더블클릭하는 표준 경로가 없다. 만들어지는 파일 자체는 같다.

새로 확인했다면 날짜·OS·확인한 사람·실제 실행기 여부를 함께 적고 해당 칸을 바꿉니다.

## 5. 예상 질문과 답

**Q. 인터넷에 내 대화나 파일이 올라가나요?**
A. 관리 화면은 이 컴퓨터 안(loopback 주소)에서만 열립니다. 채팅 기록과 등록한 문서는
`OMM_HOME` 아래에 저장됩니다. 채팅 기록은 사용 통계에 포함되지 않습니다(`docs/local-web.md`). 사용 통계·오류 보고·벤치마크 업로드는
모두 사용자가 직접 켜야 동작합니다(`PRIVACY.md`). 모델을 받을 때와 사용자가 누른 확인 버튼은
인터넷을 씁니다.

**Q. 저장 공간이 얼마나 절약되나요?**
A. 같은 모델 파일을 실행기마다 다시 받지 않고 링크합니다. 실제 절약량은 PC마다 다르며
`omm scan`이 그 PC에서 계산한 값을 보여 줍니다. 아직 여러 사용자에게서 모은 수치는 없습니다.

**Q. 추천은 얼마나 정확한가요?**
A. 추천 화면은 근거(번들 규칙, 서명된 카탈로그, 이 PC의 속도 보정)를 나눠서 보여 줍니다.
근거가 없는 경우 정확도 퍼센트를 지어내지 않고 "정보 없음"으로 둡니다.

**Q. "실행 확인"이 통과하면 좋은 모델인가요?**
A. 아닙니다. 짧은 영어 응답이 실제로 생성되는지만 확인합니다. 답의 품질은 따로 평가해야 합니다.

**Q. 컴퓨터를 켤 때마다 자동으로 켜지나요?**
A. 기본은 꺼져 있습니다. `omm setting web-autostart enable`을 직접 실행했을 때만 등록되고,
`disable`로 해제합니다. 켜져도 브라우저는 열지 않습니다.

**Q. 지우면 받은 모델도 사라지나요?**
A. 기본 제거 명령은 모델과 설정을 남깁니다. `-Purge`/`--purge`를 붙였을 때만 지웁니다.

**Q. 실제 사용자 평가 결과는요?**
A. 아직 없습니다. 3번 양식으로 기록한 뒤에만 발표 자료에 넣습니다.
