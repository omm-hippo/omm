# OMM 시연 시나리오 (녹화용)

관련 문서: [pitch-message.md](pitch-message.md) · [presentation-outline.md](presentation-outline.md) ·
[mentoring-demo.md](mentoring-demo.md) · [local-web.md](local-web.md) · [agent-connections.md](agent-connections.md)

멘토링 결론: 시연은 핵심 장면 2~3개, 각 1~3분짜리 **미리 녹화한 영상**으로 준비하고, 현장 시연은 영상이 안 될 때의
대안으로만 씁니다. 세 영상은 한 사람의 이야기로 이어집니다.

> **이야기:** 작은 회사의 신입 "지민"이 회사 노트북에 로컬 AI를 처음 세우고(A), 사내 문서와 코딩 도우미를
> 로컬로 쓰고(B), 큰 모델이 필요해지자 쉬고 있는 Mac mini들을 묶는다(C).

규칙:

- 명령·메뉴·버튼 이름은 현재 코드에서 확인한 그대로 씁니다. 화면 문구가 바뀌면 이 문서도 같이 고칩니다.
- 녹화한 결과는 실제 실행기에서 나온 것만 씁니다. 테스트용 가짜 응답으로 대신하지 않습니다.
- 시연 C의 `omm cluster`는 아직 `main`에 없는 브랜치(`docs/exo-cluster-plan`) 기능입니다. 영상에 "개발 중" 자막을 넣습니다.
- `<모델>`은 녹화 직전에 정한 실제 이름으로 바꿉니다. 모델 이름을 미리 지어내지 않습니다.

## 공통 준비

- [ ] 시연용 빈 폴더를 `OMM_HOME`으로 정한다. 평소 쓰는 `~/.omm`을 건드리지 않는다.
- [ ] 화면 해상도와 글자 크기를 키운다(브라우저 125% 이상, 터미널 글꼴 18pt 이상).
- [ ] 알림 끄기, 개인정보가 보이는 탭·바탕화면 정리.
- [ ] 시연 OS·OMM 버전(`omm --version`)·실행기 버전을 녹화 기록표에 적는다.

## 시나리오 A — 처음 쓰는 사람: 설치부터 첫 대화까지 (목표 2분 30초)

증명할 것: "모델 이름을 몰라도, 추천 근거를 보고, 확인 한 번으로 실제 응답까지 간다."

사전 조건:

- 인터넷 연결, 작은 모델을 받을 디스크 여유(10GB 이상 권장).
- Ollama 또는 LM Studio. 없으면 대화 준비 단계가 설치를 시도합니다. 단, **실행 앱의 로컬 API 서버가 켜져 있어야**
  모델을 받기 전에 멈추지 않습니다(`docs/local-web.md`). 녹화 전에 서버를 켜 둡니다.
- 미리 한 번 리허설해서 걸리는 시간과 모델 크기를 확인한다. 다운로드 장면은 편집으로 줄인다(자막 "실제 4분 → 10초로 줄임"처럼 사실대로).

- 다른 모델이 이미 올라가 있으면 새 불러오기를 거절합니다(OMM은 남의 모델을 내리지 않음). 녹화 전에 실행 앱에 올라간 모델이 없게 합니다.
- 절약량을 크게 보이려면 미리 같은 모델을 Ollama와 LM Studio 양쪽에 연결해 두는 방법이 있습니다. 이 경우 자막에 "사전 준비한 상태"라고 적습니다.

## 시나리오 B — 사내 문서 질문 + 코딩 도우미를 로컬로 (목표 3분)

증명할 것: "문서와 질문이 이 컴퓨터 밖으로 나가지 않고, 답에 출처 구간이 붙는다. 코딩 도우미도 로컬 모델로 바꾸고 되돌릴 수 있다."

사전 조건:

- 시나리오 A가 끝나 모델 하나가 Ollama 또는 LM Studio에 연결되어 있음.
- 시연용 문서: **텍스트 PDF**(스캔 PDF 아님), TXT, Markdown, HTML, HWPX 중 하나. 파일당 6 MiB 이하, PDF 100쪽 이하.
  실제 회사 자료 대신 공개해도 되는 문서(예: 가상 회사의 "출장 규정" 문서)를 직접 만들어 씁니다.
- 질문은 **문서에 실제로 있는 단어**를 넣어 준비합니다. 검색이 단어 기반(`local_lexical_v1`)이라 뜻만 같은 다른 단어는 못 찾습니다.
- 후반부(코딩 도우미): Ollama 0.14.0 이상, Claude Code(또는 Codex CLI) 설치, **도구 호출을 지원하고 문맥 길이 32K 이상**인
  Qwen 계열 모델을 Ollama에 받아 둠(64K 이상 권장). 조건이 안 맞으면 OMM이 설정을 바꾸기 전에 멈춥니다.

## 시나리오 C — 쉬고 있는 Mac mini 묶기 (개발 중, 목표 2분 30초)

증명할 것: "한 대에 안 들어가는 큰 모델을, 이미 있는 Mac 여러 대를 묶어 돌리고, 사내망에서는 토큰이 있어야만 쓴다."

**상태:** 브랜치 `docs/exo-cluster-plan`(팀원 minigu5)에서 개발 중이며 `main`에 병합되지 않았습니다. 아래 명령은 그 브랜치의
`src/omm/cli.py`와 `docs/commands.json`에서 확인했습니다. 실측 기록은 그 브랜치의
`docs/superpowers/specs/2026-10-22-exo-cluster-spike-findings.md`와 이슈 #508에 있습니다.

사전 조건(모두 실측 문서 기준):

- macOS 26.2 이상 Mac 여러 대(실측: M4 Pro Mac mini 3대). RDMA를 쓰려면 모든 Mac의 OS 버전이 같아야 합니다.
- Thunderbolt 케이블로 서로 연결(실측: 3대 삼각형). 모든 Mac에 OMM(브랜치 버전) 설치.
- RDMA 켜기는 각 Mac을 복구 모드로 부팅해 `rdma_ctl enable`로 사람이 직접 해야 합니다. OMM은 점검만 합니다.
- Mac마다 관리자 암호를 한 번 입력합니다(pf 방화벽). 새 Mac에서 처음 실행하면 **화면에 허용 창**이 떠서 눌러야 합니다.
- 큰 모델은 **미리 받아 둡니다.** 실측에서 각 Mac이 전체 파일(약 130.7GB)을 받아 첫 준비에 약 85분 걸렸고,
  `omm cluster model`은 60분 제한에 걸려 실패로 보였습니다(#508 남은 문제). 녹화는 받아 둔 뒤에 합니다.

| C8 | 분산 처리 보이기 (2:20~2:30) | 3대 화면 분할 | 각 Mac의 활동 상태(예: 활동 모니터)를 동시에 녹화 | "요청 하나를 세 대가 나눠 처리합니다." | 세 대가 동시에 일하는 모습 | **이 시각화 화면은 OMM에 없습니다(구현 예정).** macOS 기본 도구로 녹화한 화면이라고 자막에 적음 |

정리(녹화 후): 각 Mac에서 `omm cluster leave`(확인을 건너뛰려면 `--yes`). 실측에서 `leave`는 node1에서만 원래 상태 복원을
확인했습니다. 나머지 Mac은 미검증입니다.

이 시나리오에서 하지 말 것:

- "더 빠르다"고 말하지 않기(비교 실측 없음). "한 대로 못 하는 걸 한다"고 말하기.
- Windows PC를 노드로 묶는 장면(지원 대상 아님).
- RDMA 켬/끔 속도 차이(미검증).
