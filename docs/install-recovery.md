# 설치 중단 후 재개

동일한 `omm install ...` 명령을 다시 실행하면 이전 파일과 연결 상태를
다시 확인한다. 체크섬을 검증한 다운로드는 재사용하고, 엔진별 연결은 기존
소유권 검사와 멱등 연결 로직을 거쳐 확인·복구한다. 등록이 끝나기 전에
프로세스가 죽어도 작업 기록은 남는다.

기록은 `OMM_HOME/install-journal`에 모델별로 저장한다. 기록 파일을 잠가
같은 모델의 설치가 겹치지 않게 하며, 정리 명령도 같은 잠금을 잡고 삭제한다.
이 잠금은 다운로드 완료 후 연결·등록 중인 시간까지 보호한다. 기록의 체크섬만
믿지 않고 파일을 다시 해시 계산한다. 원본 URL은 기록에 저장하지 않고 출처를
비교할 수 있는 해시만 남긴다. 전송되는 데이터는 없다.

- 체크섬 확인 후 중단된 일반 설치: 파일을 보존하고 재실행을 안내한다.
- 파일이 바뀌었거나 출처가 검증되지 않음: 자동 덮어쓰기·채택을 거부한다.
- 일부 엔진 연결 실패: 등록된 정상 연결과 파일을 유지하며 재시도 대상에 남긴다.
- 기록 손상: 원본 기록을 백업하고 파일/원격 체크섬/등록 정보로 다시 확인한다.
- `omm doctor`: 미완료 기록과 원래 명령을 재실행하라는 안내를 읽기 전용으로 표시한다.
- `omm cleanup`: 실행 중인 설치는 건드리지 않는다. 실행 중이지 않은 미등록
  파일은 기존의 명시적 정리 대상이다. 이후 재실행은 필요한 파일을 다시 받는다.

일반 설치의 파일·연결·등록 복구가 대상이다. 기여용 자동 벤치마크 루프는 기존
후보별 정리 정책을 유지한다. 기록의 설치 완료와 실제 런타임 생성 검증 결과는
별개이며 `runtime_status`에 따로 남긴다. 네트워크가 필요한 모델 주소 해석이나
원격 체크섬 확인까지 오프라인으로 바뀌는 기능은 아니다.

검증은 샌드박스 파일과 엔진 연결 대역을 사용한다. 실제 프로세스를 등록 직전에
종료하고 새 프로세스로 재개하는 검사도 포함한다. 이 검사는 설치 상태 복구를
검증하며 실제 LLM 추론이 성공했다는 증거는 아니다.
