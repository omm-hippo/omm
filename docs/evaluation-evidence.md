# 추천 평가의 통과와 자료 부족

`omm setting catalog-status`는 이미 받은 추천 모델의 평가 기록을 읽는다.
새 데이터를 받거나 벤치마크를 실행하지 않는다. `--json`도 지원한다.

- `passed`: 기록된 비교 기준에서 허용 범위를 넘는 악화가 없었다.
- `failed`: 비교 기준보다 나빠졌다.
- `insufficient_data`: 사례 수, 비교 지표, 기준 중 필요한 근거가 부족하다.

통과는 해당 평가와 자료 범위에 대한 결과이며, 모든 PC에서 실행되거나 모든
작업에서 좋은 답변을 낸다는 뜻이 아니다. 속도/선택/적합성 항목을 따로 표시한다.
필요한 최소 사례 수와 추가로 필요한 개수도 표시한다. 최소 개수 충족 자체가
하드웨어 전체를 대표하는 데이터라는 뜻은 아니다.

과거 artifact의 `evaluation.passed`는 공개 여부를 정하는 회귀 게이트였다.
부적합 사례가 부족하면 적합성 지표 판정을 건너뛰므로 이 값만으로 모든 항목이
검증됐다고 해석하면 안 된다. 새 `evaluation_details`는 이를 구분하고,
오래된 파일도 원본을 수정하지 않고 같은 기준으로 설명한다.

이번 변경은 기존 공개 정책과 수치 기준을 바꾸지 않는다. 학습 로그와 자동 PR
설명에도 미평가 항목을 드러낸다. 자료 부족을 이유로 기준을 낮추거나 측정을
자동 시작하지 않는다. 부족한 측정은 사용자 동의와 기존 메모리 보호 아래에서
수집해야 한다. 실제 학습·업로드·운영 배포는 별도 작업이다.
