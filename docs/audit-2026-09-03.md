# 2026-09-03 감사 수정과 설치 단계 통합

이 변경은 Claude의 PR #271 수정과 Codex의 후속 수정안을, PR #253이 병합된
`main`(`4387857`) 위에 통합한 결과다. npm 배포 경로는 별도 PR #270에서 다룬다.

## 수정한 사용자 경로

- 설치: 용량 검사가 실패하기 전에 기존 모델을 지우지 않는다. 강제 재설치 때 회수할
  공간은 실제 정리 대상의 일반 파일과 마지막 hard link에만 인정하고, sparse 파일의
  논리 크기·symlink 대상·다른 볼륨의 공간을 부풀려 계산하지 않는다.
- 설정: 동시 첫 실행이 이미 저장된 설정을 초기값으로 덮지 않으며, 설치 식별자도
  한 번만 생성한다. 손상된 설정의 백업·읽기 처리는 공통 함수에 모았다.
- 모델 정리: Ollama의 저장소 잠금 안에서 `latest` 외 일반 태그도 확인한다. 잘못된
  Jan manifest 하나가 전체 모델 검색을 중단하지 않는다.
- 모델 교체: native Ollama 교체가 실패하면 이전 manifest 내용·파일 권한·소유권을
  복원하고 이전 blob을 보존한다. 성공한 뒤에만 다른 모델이 참조하지 않는 이전
  owned blob을 정리한다. 복원 실패는 숨기지 않고 오류로 알린다.
- 런타임: 로컬 API의 리다이렉트를 거부하고, LM Studio 해제는 OMM이 소유한 정확한
  instance ID로 확인한다. 다른 클라이언트 인스턴스를 해제 실패로 오판하지 않는다.
- 취소: 버려진 벤치마크 스레드가 인터프리터 종료를 막지 않는다. 이미 취소가 요청된
  작업은 새 스레드로 시작하지 않는다. 실행 중인 임의 함수 자체를 강제 중단한다는
  보장은 없으며, 실제 기본 quality 평가는 기존 별도 프로세스 취소 경로를 유지한다.
- 데이터 공유: 생성 실패의 `0.0 tok/s`는 업로드 동의 경로에 들어가지 않는다.
  중앙 텔레메트리의 비정상 수치 검사와 원래 실패 사유 보존을 함께 유지한다.
- 기타 Claude 수정: 실패한 데몬 시작 정리, import 부분 복사본 정리, 손상된
  benchmark history 백업, GPU 기준 규칙 정렬, 메모리 회수 우선순위, GPU 벤더
  판정, 온보딩 Esc 처리, Windows 앱 이름 판정, 학습 자료 부족 예외,
  수동 버전 변경 시 npm 런처 동기화, 동일 커밋 업데이트 처리를 보존했다.

## 구조 정리와 충돌 해소

`_prepare_install_artifact()`는 기존 파일 확인, 다운로드, 용량 검사, 취소 처리와
체크섬 검증을 맡는다. `_install_impl()`은 후보 정책 → 파일 준비 → 링크·등록 →
런타임 검증·벤치마크 순서를 나타낸다. 공개 명령과 옵션은 바꾸지 않았다.
상세 경계는 [설치 단계 문서](install-staging-flow.md)에 있다.

설정 읽기 중복은 `_read_config_data()` 하나로 통일했다. `autoremove_ollama()`의
잠금과 모든 태그 순회를 결합했고, 양쪽 설치 회귀 테스트를 모두 남겼다.
추천 결과 표시, SHA-256 정규화, 수치 검증, 모델 인스턴스 파싱도 공통 규칙을 쓴다.
복구·소유권·동의 확인 분기는 단순화를 이유로 제거하지 않았다.
