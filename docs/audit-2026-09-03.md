## 2. #271이 바꾼 계약·시그니처 (코드를 만질 때 알아야 할 것)

`src/omm/cli.py`
- `_lookup_entry(filename, reg) -> (tried_name, entry | None)`: miss일 때 `(None, None)` 대신 `(시도한 .gguf 이름, None)`. 호출부 11곳은 `entry`만 검사한다. `remove()`가 이 헬퍼를 재사용한다.
- `_run_interruptible(fn, stop_event)`: `ThreadPoolExecutor` 대신 데몬 스레드(이름 `omm-interruptible`). `fn`의 예외는 호출 스레드에서 재발생. 취소 후에도 `fn`은 백그라운드에서 계속 돌지만 인터프리터 종료를 막지 않는다.
- `_install_impl`: `tokens_per_sec`가 `0.0`(생성 시도 후 실패)이면 `_report_telemetry(filename, repo_id, None, failure_reason="generation_failed", ...)`로 넘긴다. `telemetry.log_attempt("skipped_generation_failed")`. 업로드 동의 경로(`want_upload`)에 절대 들어가지 않는다.
- `_install_impl`: omm이 직접 띄운 Ollama(`ollama_daemon_handle`)가 health 재확인에 실패하면 그 자리에서 `_stop_engine_daemon("ollama", handle)`.
- 신설: `_present_recommendations(info, ranked, refs, installations, profile, *, json_output, auto_yes)`, `_download_update(url, tmp, filename) -> bool`, `_reject_conflicting_policy_flags(enable, disable, ask)`, `_entry_size_bytes(filename, entry) -> int | None`. `_print_contribution_summary(..., engine="ollama")` 인자 추가(요약이 실제 엔진 이름 표시).
- 삭제: `_cached_remote_head_commit`(호출자 없음), `_managed_model_path`의 불가능한 `isinstance` 분기, `_EscListener._run_posix`의 도달 불가 win32 분기(`start()`가 Windows에서는 `_run_windows`로 보냄).

다른 모듈
- `featurize.positive_finite_number(value) -> float | None` 공개 헬퍼(이전 `_positive_finite_number`). `predictor.estimate_required_memory_gb`, `tuning.candidate_model_size_gb`, `quality._generate_lmstudio`가 import. `cli.py`의 bool 반환 `_positive_finite_number`는 별개로 그대로.
