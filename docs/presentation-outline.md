# OMM 발표 슬라이드 구성 (45장)

관련 문서: [pitch-message.md](pitch-message.md) · [demo-scenarios.md](demo-scenarios.md) · [mentoring-demo.md](mentoring-demo.md)

원칙(멘토링):

- **한 장에 한 메시지.** 제목 자체가 그 장의 주장입니다.
- 흐름: 문제 → 기존 방식 한계 → 해결 → 동작 → 기술 → 효과 → 확장.
- 심사위원 전공이 다양합니다(임베디드, 시스템, 컴파일러, 소프트웨어공학). 로컬 AI·모델·양자화 같은 기초부터 설명합니다.
- 숫자는 실측한 것만 씁니다. 출처가 브랜치 실측 문서인 숫자는 슬라이드 아래에 작게 "개발 중 브랜치 실측(2026-10-24)"이라고 적습니다.
- 아직 없는 것은 "구현 예정", 사람이 확인하지 않은 것은 "미검증"으로 표시합니다.

표 열: 번호 · 제목(한 문장 메시지) · 핵심 그림 · 발표자 한 줄 메모.

## 1부. 문제 (1~9)

| # | 제목 | 핵심 그림 | 발표자 메모 |
|---|---|---|---|
| 1 | 서버 없이, 내 컴퓨터로, 내 자료를 밖에 보내지 않는 AI | OMM 로고 + 노트북·Mac mini 사진 | "팀 하마, OMM을 소개합니다." |
| 2 | 우리는 한 사람의 이야기로 설명합니다 | 신입 "지민" 캐릭터와 회사 노트북 | "작은 회사 신입 지민이가 AI를 세우라는 일을 받았습니다." |
| 3 | 많은 회사는 내부 자료를 외부 AI에 보낼 수 없습니다 | 문서 → 클라우드에 빨간 X | "보안 규정 때문에 ChatGPT 같은 서비스에 사내 문서를 못 올립니다." |
| 4 | 로컬 AI란, 내 컴퓨터 안에서 도는 AI입니다 | 클라우드 vs 내 PC 두 그림 비교 | "질문과 답이 이 컴퓨터 밖으로 나가지 않는 방식입니다." |
| 5 | 로컬 AI에는 '모델 파일'과 '실행 앱' 두 가지가 필요합니다 | 모델 파일(GGUF) + 실행 앱(Ollama, LM Studio) 블록 | "모델은 두뇌 파일, 실행 앱은 그걸 돌리는 프로그램입니다." |
| 6 | 처음 하는 사람은 "어떤 모델이 내 PC에 맞나"에서 막힙니다 | 수많은 모델 이름 목록과 물음표 | "같은 모델도 크기·양자화(Q4 등)가 여러 개라 고르기 어렵습니다." |
| 7 | 모델을 받아도 실제로 답하는지 확인하기 어렵습니다 | "다운로드 완료" → 그런데 응답은? | "파일이 있다고 실행되는 건 아닙니다. 메모리 부족이 흔합니다." |
| 8 | 실행 앱마다 같은 모델을 또 받아 저장 공간이 두 배로 듭니다 | 같은 파일 두 개 그림 | "Ollama와 LM Studio를 같이 쓰면 같은 파일을 두 번 받습니다." |
| 9 | 큰 모델은 GPU 서버가 필요하다고 생각하지만, 사무실엔 쉬는 기기가 있습니다 | GPU 서버 가격표 vs 밤에 꺼진 Mac mini들 | "새로 사는 대신 이미 있는 걸 쓰면 어떨까요?" |

## 2부. 기존 방식의 한계 (10~14)

| # | 제목 | 핵심 그림 | 발표자 메모 |
|---|---|---|---|
| 10 | 실행 앱은 '돌리는 것'까지만 합니다 | 흐름도: 고르기·확인·연결이 비어 있음 | "Ollama, LM Studio는 훌륭하지만 앞뒤 과정은 사용자 몫입니다." |
| 11 | 문서 질문·코딩 도우미 연결은 또 따로 설정해야 합니다 | 설정 파일 여러 개 | "도구마다 연결 방법과 설정 파일이 다릅니다." |
| 12 | 여러 기기 묶기 도구(exo)는 있지만 보안·네트워크는 직접 해야 합니다 | exo 포트가 사내망에 열린 그림 | "exo API는 기본적으로 인증 없이 열립니다(OMM 실측)." |
| 13 | 클라우드 API는 쉽지만 자료가 밖으로 나갑니다 | 데이터 화살표가 외부 서버로 | "가장 쉬운 길이지만 이번 대상에게는 막힌 길입니다." |
| 14 | 비교하면, 고르기부터 운영까지 한 번에 잇는 도구가 비어 있습니다 | 경쟁 비교표 요약(pitch-message 5절) | "OMM은 실행 앱을 대신하지 않고, 그 사이를 잇습니다." |

## 3부. 해결 (15~19)

| # | 제목 | 핵심 그림 | 발표자 메모 |
|---|---|---|---|
| 15 | OMM은 내 업무에 맞는 로컬 AI를 쉽고 안전하게 세우는 오픈소스 플랫폼입니다 | 한 줄 메시지 크게 | "한 줄로 말하면 이겁니다." |
| 16 | 대상은 처음 쓰는 사람, AI 담당자 없는 중소기업, 자료를 못 내보내는 조직입니다 | 세 사람 아이콘 | "세 대상 모두 '쉽고 안전하게'가 필요합니다." |
| 17 | 네 가지 가치: 쉬움 · 안전 · 저비용 · 단계적 확장 | 네 칸 그림 | "이 네 단어만 기억해 주세요." |
| 18 | 한 대에서 시작해서, 필요하면 여러 대로 키웁니다 | 계단: 한 대 → 문서 → 코딩 도우미 → 여러 대 | "처음부터 큰 투자가 필요 없습니다." |
| 19 | 전체 흐름: 분석 → 추천 → 준비 → 대화 → 문서 → 도우미 → 묶기 | 가로 흐름도 | "이 흐름을 영상 세 개로 보여 드리겠습니다." |

## 5부. 기술 (24~33)

| # | 제목 | 핵심 그림 | 발표자 메모 |
|---|---|---|---|
| 24 | 구조: OMM은 실행 앱 위에서 고르기·연결·확인을 맡습니다 | 계층도: 웹/CLI → OMM → Ollama·LM Studio·exo | "실행 앱은 그대로 두고 그 위에 올라갑니다." |
| 25 | 하드웨어를 읽고, 근거와 함께 추천합니다 | 추천 화면 캡처 + 근거 유형 표 | "근거가 부족하면 '부족하다'고 표시합니다. 정확도 숫자를 지어내지 않습니다." |
| 26 | 추천 자료는 서명을 확인한 뒤에만 씁니다 | 서명 → 검증 → 사용 흐름 | "추천 카탈로그는 Ed25519 서명을 확인합니다." |
| 27 | 대화 준비는 여섯 단계를 하나의 작업으로 묶습니다 | 6단계 진행 막대 | "실행 앱 확인 → 안전 검사 → 서버 확인 → 파일 → 연결 → 실제 응답. 현재 Ollama·LM Studio 지원." |
| 28 | 모델 파일은 한 곳에 두고 실행 앱에는 링크합니다 | 허브 하나 → 앱 여러 개로 화살표 | "하드링크 → 심볼릭 링크 → 복사 순서로 시도합니다." |
| 29 | 다른 앱이 쓰는 메모리는 건드리지 않습니다 | 메모리 막대 + "남의 모델 내리지 않음" | "여유가 없으면 멈추고 이유를 보여 줍니다." |
| 30 | 문서 질문은 이 컴퓨터 안의 단어 검색으로 근거를 찾습니다 | 문서 → 조각(900자) → 검색 → 로컬 모델 → 답+출처 | "SQLite에 저장, 네트워크 호출 없음. 임베딩 모델이 필요 없습니다." |
| 31 | 지원 문서와 한계를 먼저 말합니다 | 형식 표: 텍스트 PDF·TXT·MD·HTML·HWPX / 스캔 PDF·HWP 미지원 | "파일당 6 MiB, PDF 100쪽, 문서 100개까지. 뜻만 같은 단어는 못 찾습니다." |
| 32 | 코딩 도우미 연결은 백업 → 연결 → 복원 순서로 안전하게 합니다 | 설정 파일 3개(Claude·Codex·pi) + 백업 폴더 | "도구 호출 지원과 32K 문맥이 없으면 설정을 바꾸기 전에 멈춥니다." |
| 33 | 클러스터는 exo 위에 방화벽·토큰 게이트웨이·상태 점검을 얹습니다 (개발 중) | 사내망 ↔ 게이트웨이(52440, 토큰) ↔ Mac들(Thunderbolt) | "exo 포트는 사내망에서 닫혀 있고 게이트웨이만 열립니다(실측 포트 스캔)." |

| 38 | 오픈소스로 공개하고, 검증 기록을 남기며 개발합니다 | 저장소 화면: MIT, CI 3개 OS, 설계·실측 문서 | "모든 병합은 리뷰를 거치고, 릴리스는 서명 태그로 합니다." |
