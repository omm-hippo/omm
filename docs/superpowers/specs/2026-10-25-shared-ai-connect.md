# 공유 AI 연결·진단 화면

## 목적과 범위

공유받은 직원 PC에서 주소·토큰을 입력하고 모델을 선택해 실제 첫 응답을
확인한다. 클러스터 엔진/RDMA/모델 관리, 기존 RAG 저장 설정, 에이전트 설정은
바꾸지 않는다. 기존 OMM 작업 공간의 조판·내비게이션을 유지한다.

## 사용 흐름

1. `omm web` → **공유 AI** → 사내망 또는 Tailscale 주소와 직원 토큰 입력.
2. 사용자가 연결 확인을 누르면 `/v1/models`로 인증·지원 응답을 확인한 뒤 저장.
   빈 토큰은 같은 주소의 저장된 토큰에만 적용한다. 실패하면 이전 설정을 보존한다.
3. 모델은 자동 선택하지 않는다. 목록이 실행 중인 모델 목록이 아니라는 점을
   안내하고 관리자가 알려준 모델을 고르게 한다.
4. 첫 질문을 실제로 전송하고 정상 응답을 받았을 때만 응답 확인 상태로 표시한다.
5. 새로고침 시 주소·토큰·마지막 목록·마지막 성공 모델을 복원하되 대화는 복원하지 않는다.
6. 연결 삭제는 로컬 설정만 삭제한다. 서버의 토큰·모델은 건드리지 않는다.

## 경계

- 기존 세션 쿠키·Host·Origin·명시 작업 헤더를 모든 새 API에도 적용한다.
- 연결은 명시적 동작으로만 수행한다. 상태 읽기·화면 전환·새로고침은 외부 호출하지 않는다.
- 사설 LAN, Tailscale CGNAT, IPv6 ULA만 허용. DNS의 모든 주소를 검사하고
  요청 중 주소를 고정한다. loopback, link-local/metadata, 공인 주소, 프록시,
  리다이렉트, 인증서 검사 해제는 지원하지 않는다.
- 원문 서버 오류·토큰을 사용자 오류/로그로 돌려주지 않는다. 네트워크 실패만으로
  Tailscale이 꺼졌다고 단정하지 않는다. 404도 버전 문제로 단정하지 않는다.
- 401/403, 429/402, 네트워크, 인증서, 응답 형식, 모델 요청 실패를 구분한다.
- 질문의 UUID와 본문 지문을 검사해 최근 동일 요청의 중복 생성을 막는다.
  실패 후 자동 재시도하지 않는다. 서버 처리 상태가 불확실하면 재연결을 안내한다.
- 512 출력 토큰, 25개 메시지/48,000자 요청, 2 MiB 응답으로 제한한다.
- 토큰은 별도 비공개 디렉터리·파일에 저장한다. 대화는 메모리에만 보관한다.

## 검증 계획

실제 loopback HTTP fixture로 세션·권한·설정 저장·재접속·오류·중복 요청을 검사한다.
실제 공유 서버 검증과 fixture 결과는 따로 기록한다. 사용자 브라우저·마우스·키보드에
영향을 주지 않는 headless 브라우저에서 데스크톱·모바일·한국어 입력을 확인한다.
