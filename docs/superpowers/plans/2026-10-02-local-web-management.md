# Local manager components and acceptance

1. Serve the bundled interface and management API from one loopback origin.
2. Keep file operations serialized, idempotent and recoverable through durable jobs.
3. Run response checks separately from installation and preserve runtime ownership.
4. Share provenance and checkpoint descriptions between browser and CLI views.
5. Include click launchers and explain missing runners and first-use steps.
6. Validate real browser requests, persisted bytes, runner-side results, restart
   recovery, narrow layouts and distributable assets.

Acceptance distinguishes fixture contracts from live runtime results. Human
usability evaluation, real Windows installation and native launcher clicks need
separate evidence. Checkpoint/device coverage is unknown when source metadata
cannot establish it; a tree-disagreement interval is not calibrated confidence.
