# OMM 시스템 및 사용 흐름 개선

사용자가 설명을 검토하고 2026-09-16에 구현을 승인했다. 기준은 main
`b9ee646`; 작업은 `one-way/system-ux-reliability-20260916`에서 수행한다.

## 승인된 범위와 순서

1. CLI 중복 export 정의를 제거하고 출력/작업 로직을 작게 분리한다.
2. JSON 출력에는 결과 문서만 남긴다. 진행/경고는 stderr로 보낸다.
   기존 성공 데이터의 구조는 유지하고 실패/취소도 기계적으로 구분한다.
3. 추천 평가에 통과/실패/자료 부족을 항목별로 기록한다. 미평가를 검증된
   결과로 표시하지 않는다. 공개 artifact 자체를 수동으로 수정하지 않는다.
4. 모델 설치에 영속 작업 기록과 잠금을 추가한다. 재시작 시 기록만 믿지
   않고 실제 파일/체크섬/연결 상태를 확인한다. 검증된 다운로드는 재사용하고
   누락된 연결과 등록을 복구한다. 다른 작업이나 사용자의 파일은 정리하지 않는다.
5. #339: scan 기본 출력은 메모리/저장/모델/설치된 엔진 중심, OS/CPU/GPU는
   상세 보기로 이동한다. 엔진 이름을 상태보다 강조하고 터미널 폭에 맞춘다.
   밝은/어두운 배경과 no-color에서 역할별 가독성을 확인한다.
6. #332: 길고 반복되는 오류 도움말 대신 짧은 설명과 --help 경로를 표시한다.
   같은 터미널에서 같은 안내를 반복하지 않는다. 파이프/JSON에는 안내를 섞지 않는다.
7. #336: 엔진 설치 단계와 경과 시간을 표시하고 상태/진단/업데이트/제거를
   설치 출처에 맞게 지원한다. 외부에서 설치된 앱의 출처를 추정해 삭제하지 않는다.
8. tune: 제안 → 임시 적용 → 실제 생성 검증 → 저장/복원. 모델 해시와 엔진별
   프리셋을 저장하고 OMM 실행 경로에서 사용한다. 로드된 타 모델은 건드리지 않는다.
   실측 속도와 실행 성공을 답변 품질 향상으로 표현하지 않는다.

## 확인할 경계

- 원래 checkout, 사용자 ~/.omm, 설치된 OMM, 개인 앱/모델 데이터를 보존한다.
- 테스트는 작업 전용 환경과 임시 OMM_HOME으로 실행하고 외부 네트워크를 막는다.
- 실제 로컬 엔진 검증이 가능한지 읽기 전용으로 조사하고 다른 작업과 충돌하지
  않는 범위만 검증한다. 불가능한 환경은 정확히 미검증으로 기록한다.
- 구현/단위검증/실제 엔진/실물 장비 검증을 구분한다.
- 서명, 업로드 동의, 패키지 관리자의 소유권 계약은 유지한다.
- 후속 사용자 지시로 push/PR 게시가 승인됨. 먼저 완료된 묶음을 먼저 게시하고,
  이전 PR의 실제 병합을 확인한 뒤 다음 PR을 게시한다. 비슷한 시점에 끝나는
  관련 변경은 묶는다. merge/release/production 배포 권한으로 확대하지 않는다.
- 운영 OMM HTTP 요청 예산 사용: 0회.

## 토의 해석

#336은 댓글이 없어서 작성자의 제안을 구현 범위로 삼는다. #339는 CPU/GPU/OS
표시 축소와 정보 강조의 중요성에 대한 후속 의견을 반영한다. 배경색 자동 추정은
확실한 신호가 없으면 터미널 기본색을 존중한다. #332의 터미널당 1회 안내는
최종 합의라고 주장하지 않고 사용자가 승인한 설계의 선택으로 적용한다.

### 첫 묶음 확인 사항

벤치마크 성공 JSON은 기준 코드에서 이미 단일 문서였다. README의 오래된 설명을
바로잡고, 공통 직렬화와 실패/취소 문서 및 중복 명령 방지를 보완한다.

첫 묶음 검증: 관련 회귀 305 passed. 업로드 오류 JSON 오염을 재현 후 수정하고
관련 최종 검사 158 passed (검사 집합은 일부 겹침). 이 Mac에서 임시 OMM_HOME으로
실제 scan / scan --details / scan --json 명령이 모두 exit 0이고 JSON 해석에 성공했다.
엔진 추론, Windows/Linux 실물 및 배포 패키지 경로는 이번 묶음에서 미검증이다.
