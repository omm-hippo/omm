# 원하는 만큼 기여하기

```sh
omm contribute --max-minutes 30 --max-download-gb 10 --max-models 3
```

이 예시는 30분, 모델 데이터 10 GiB, 새 모델 3개라는 한도를 함께 적용한다.
각 옵션은 따로 쓸 수 있다. 아무 한도도 선택하지 않으면 기존처럼 Esc로 멈추거나
후보를 모두 살펴볼 때까지 계속한다. `--yes`는 시작 확인을 생략하므로 안내된
반복 다운로드와 결과 전송을 이해한 경우에 사용한다.

- 시간 한도는 실제 기여 루프가 시작할 때부터 계산한다. 시간이 되면 다운로드와
  평가에 중단을 요청한다. 진행 중인 네트워크 호출이 돌아오거나 파일을 안전하게
  정리하는 데에는 시간이 조금 더 걸릴 수 있다.
- 다운로드 한도는 읽어 온 모델 본문 바이트를 합산한다. 재시도하면서 다시 받은
  바이트도 포함한다. 모델 정보 조회, HTTP/TLS 헤더 등 통신 부대 비용은 제외한다.
  남은 한도보다 큰 것으로 확인된 모델은 받지 않고, 크기를 모르는 응답은 한도에서
  중단한다. 한도가 있으면 본문을 순차적으로 읽어 동시에 진행 중인 읽기의 초과를 막는다.
- 모델 수 한도는 새로 시도한 모델의 수다. 같은 모델의 재시도는 다시 세지 않는다.
  이미 보유한 모델이나 다른 작업이 사용 중인 모델은 한도를 소모하지 않고 보존한다.

원래 있던 모델 파일, 등록 정보, 엔진 연결, 부분 다운로드는 자동 기여 작업에서
보존한다. 메모리 보호 과정에서 다른 OMM 관리 모델의 메모리 로드를 해제할 수는
있지만 저장된 모델 파일을 삭제하지는 않는다. 기존 모델을 직접 측정하고 싶으면
`omm benchmark`를 사용한다.
새 모델은 같은 파일을 사용하는 다른 OMM 작업과 겹치지 않도록 잠근 뒤 처리한다.
성공·실패·취소·재시도 정리는 그 잠금 안에서 이번 실행 소유 파일에만 적용한다.
프로세스를 강제로 죽이거나 전원이 꺼진 경우에는 정리가 끝났다고 보장하지 않는다.

시작 안내는 반복 작업과 자원 사용, 전송 항목, 공개 여부, 선택한 한도를 보여준다.
기본 수집기의 벤치마크 결과는 공개 데이터다. 모델 식별 정보·기기 특성·버전·속도와
평가 요약이 포함되며 생성 문장과 개인 파일 경로는 전송하지 않는다. 사용 통계와
오류 보고는 별도의 기존 동의 설정을 유지한다.

종료 요약은 측정 완료, 수집기가 수락한 속도 결과, 재전송용으로 실제 저장된 실패,
보류/실패 이유와 보존·삭제·정리 실패 파일을 구분한다. 수집기의 수락은 학습에
채택됐다는 뜻이 아니다. 임시 모델을 지웠더라도 전송에 실패할 수 있고,
기존 파일을 보존했다고 해서 그 파일을 이번에 측정했다는 뜻도 아니다.

로컬 속도 보정은 실제 측정한 엔진별로 계산·저장한다. LM Studio 측정으로
Ollama의 보정값을 바꾸지 않는다.
